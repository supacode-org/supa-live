# 更名為 Supa Live

## 摘要

產品名從 SupaLive 改成 Supa Live，GitHub 倉庫從 `supalive` 改成 `supa-live`。crate 名和命令列指令跟著倉庫名改，Bundle ID 改到 supacode 組織底下。舊版使用者升級後，直播間、錄製紀錄和設定照常保留。

## 名稱

| 項目 | 新名稱 |
| --- | --- |
| 產品名（視窗標題、介面文字、App 名稱、安裝程式） | `Supa Live` |
| GitHub 倉庫 | `supacode-org/supa-live` |
| Bundle ID | `org.supacode.app.live` |
| crate | `supa-live`（命令列）、`supa-live-core`、`supa-live-desktop` |
| 命令列指令 | `supa-live` |
| 預設錄製根目錄 | `~/Downloads/Supa Live` |
| 發佈檔名 | `Supa-Live_<版本>_…`（桌面版）、`supa-live-cli_<版本>_…`（命令列） |

- 發佈檔名用連字號：Tauri 以產品名當安裝檔檔名，裡面有空格，GitHub 上傳時會把空格換成點。`tools/release.sh` 複製到 `dist/` 時把 `Supa Live_` 換成 `Supa-Live_`。
- 以下沿用舊名，使用者看不到，改了只會多一次遷移：設定檔 `supalive.json`、暫存資料夾前綴、注入腳本的全域旗標 `__supaliveSniffer`。

## 升級遷移

設定資料夾以 Bundle ID 命名（macOS 在 `~/Library/Application Support/<Bundle ID>/`，Windows 在 `%APPDATA%\<Bundle ID>\`），改 Bundle ID 後新版讀不到舊的 `supalive.json`。

- 啟動時，新設定資料夾沒有 `supalive.json`、同層的 `app.supalive.desktop/supalive.json` 存在時，把它複製過來。
- 舊檔留著不刪，降級回舊版還能用。
- 遷移過來的設定保留原本的根目錄，所以舊使用者繼續錄在 `~/Downloads/SupaLive`。新的預設根目錄只影響第一次使用的人。
- 抖音側欄的登入狀態存在 WebView 的資料裡，跟著 Bundle ID 走，搬不過來，升級後要重新登入。

Bundle ID 不同，系統會把新版當成另一個 App：macOS 上舊的 `SupaLive.app` 和新的 `Supa Live.app` 並存，Windows 上舊版也不會被新版安裝程式移除。使用者要自己刪掉舊版。

## 驗證

- `cargo test --workspace` 涵蓋遷移：舊檔會複製過來、新檔已存在時不覆蓋、沒有舊檔時不建檔。
- 編譯桌面版，打開後視窗標題和介面文字都是 Supa Live。
- 在 Leo 的 Mac 上：裝過舊版的情況下打開新版，直播間和錄製紀錄都在，錄製位置仍是原本的資料夾。
- `tools/release.sh build` 產出的檔名符合上表（下次發佈時確認）。

## 不在範圍內

- 抖音登入狀態的遷移。
- 自動移除舊版 App。
- 改名舊的錄製資料夾，或把舊錄影搬到新的預設根目錄。
- 改 GitHub 倉庫名本身，由 Leo 在 GitHub 上操作或另外同意後再做。
